# 想定类型协议

本目录定义由具体想定抽象出的稳定类型。一个想定类型描述可以复用同一套分支方案的具体想定、可用环境模板和 side。Backend 在启动时加载这些文档，并用于资源、分支方案和推演运行校验。

## 文件粒度

一个文件对应一个想定类型，而不是一个环境类型，也不是每个细微版本各建一个文件。

- `zc3`、`zc3-v2` 等兼容变体应写入同一个 `zc3.yaml`。
- 场景结构或参数语义明显不同的想定应定义新的想定类型。
- 环境模板只是想定类型的兼容属性，不应把所有 PySim 想定合并为一个类型。

`schema.example.yaml` 只用于说明和测试，不代表真实想定类型。生产配置必须在 `config/index.yaml` 中显式登记；目录中的未登记文档或登记后缺失的文档都会阻止 Backend 启动。

## 字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `schema_version` | `1` | 协议版本 |
| `kind` | `scenario_type` | 固定文档类型 |
| `key` | `string` | 全局唯一标识，只允许小写字母、数字和下划线，且必须以字母开头 |
| `name` | `string` | 想定类型显示名称 |
| `description` | `string` | 想定类型的用途和兼容边界 |
| `environment_templates` | `string[]` | 可运行该类型的环境模板 key |
| `scenarios` | `string[]` | 属于该类型的具体想定名称，精确匹配想定文件中的 `name` |
| `sides` | `object[]` | 想定类型支持的 side 与中文名称 |

每个 `sides` 元素包含：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `key` | `string` | 精确匹配想定文件解析出的 side |
| `name` | `string` | 面向业务人员显示的中文阵营名称 |
`environment_templates`、`scenarios` 和 `sides` 必须非空，且各自不能包含重复 key。所有协议值均区分大小写，不进行别名匹配、翻译、修剪或自动归一化。国旗等展示素材由 Frontend 根据 side key 管理。

`sides` 的顺序具有协议含义：第一个 side 是环境状态连接使用的默认阵营。环境实例不单独保存或选择阵营；Backend 和 Offline Client 都从关联想定类型的第一个 side 解析连接参数。

协议采用严格字段校验，未定义字段会导致校验失败。加载器同时校验跨文件的 `key` 唯一性、环境模板引用和具体想定归属。想定资源、环境资源、分支方案和推演通过 `scenarioTypeKey` 引用这里的类型。
