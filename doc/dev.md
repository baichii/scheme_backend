## 开发计划



#### 1. 工程说明

这是一个智能体调度工程的后端，整个工程由3大组件(frontend ,backend, engine)构成，设计思路为前后分离，前端仅和后端交互，后端负责和数据库，engine交互 

+ Scheme-frontend(ts + react)

  前端操作界面，增删改查，将前端的请求和配置发送给后端

+ Scheme-backend(python + fastapi + postrgesql + minio)

  处理前端请求、数据库、engine交互逻辑，后端连接环境需要通过engine转发(因为环境连接需要特定的依赖，这些依赖只安装在engine所在的容器）

+ engine(python + celery + redis + rabbitmq)

  智能体执行引擎，接受后端发送过来的执行方案，运行智能体，负责和env交互，执行动作，通过redis处理内部状态，提供智能体执行状态接口，后端定期请求获取执行中的智能体状态，将日志等数据写到rabbitmq中，供backend查询更新数据库

  

#### 2. 需求

+ 智能体管理

  + 智能体上传。格式为包含config.yaml(包含参数声明)的zip包，前端检验参数是否合法，不合法返回报错，合法点击保存后，发送给后端上传，并将信息保存到数据库中，成功则展示对应信息，同时可以添加名称和描述，点击保存，失败则返回异常信息
  + 查看、删除。已上传的智能体支持查看、删除
  + 修改。仅支持修改上传智能体的描述字段
  
+ 环境管理

  + 环境类型模版（同类型的环境）配置。支持上传环境参数模版（类似config.yaml，是一些参数声明），配置名称，保存
  + 环境配置，选择环境模版，配置需要配置的参数，保存
  + 模版查看/环境查看，删除

+ 智能体执行方案管理

  + 配置时选择阵营，选择环境类型
  + 检索支持该环境的智能体，拖动到执行区，配置参数，检查参数是否完整，完整后可保存
  + 保存成功后，支持选择环境执行（包含环境连接测试，不可连接到当前异常的环境，通过后端进行），执行成功后，支持调用后端接口获取智能体执行状态，日志信息
  + 方案执行过程中支持更新，支持停止掉一个方案中的个或者
  + 支持查看所有方案，方案可查看，可编辑

+ 和engine交互

  一个方案本质是一个list，内部的每个元素是一个容器任务或者task任务，所有和engine的交互都是基于task进行的，比如：要查询一个推演方案的运行状态，其实是先检索到这个方案中的所有智能体，然后调用查询接口，查询所有智能体状态

  + 下发，engine负责方案具体执行，一个方案下发给engine，调用create接口
  + 修改，执行过程中可以修改正在执行的方案
  + 查询，查询一个或多个智能体当前的运行状态
  + 停止，停止一个或者多个智能体运行
  + 日志获取，一个推演任务下发时，会带有自己的配置信息，engine会基于这个信息，穿件对应的消息队列，engine通过凭借ip+port+
  + 环境信息连接测试
  + health_check

+ 备注

  1期已完成一个scheme-frontend + engine的版本

  + 临时的智能体获取服务，直接参数解析，不支持上传，智能体缓存再引擎的cache中
  + 运行状态通过前端缓存实现，单机版本，具备完整的配置不支持多人查看
  + 环境类型通过配置文件在前端可选，可配置，支持选择环境，测试环境状态（前端直连环境）
  + 方案执行，状态、日志获取流程都已经调通
  + engine 1期的版本基本就是最终版
